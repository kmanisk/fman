# Contributing

Contributions are welcome. Keep changes focused and avoid mixing unrelated behavior or formatting changes in one pull request.

## Workflow

1. Branch from `main`.
2. Follow `README.md` for setup and usage, and reproduce the current behavior before changing it.
3. Make one logical change per pull request.
4. Run the relevant formatter, linter, build, and tests available in the repository.
5. Explain what changed, why, and how it was verified.

For file-management behavior, call out any filesystem assumptions or destructive operations explicitly. Never commit credentials, personal paths, local caches, generated build artifacts, or editor-specific files.
